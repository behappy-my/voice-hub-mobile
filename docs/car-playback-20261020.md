## 已修复的代码问题

| 场景 | 原代码风险 | 本轮处理 |
| --- | --- | --- |
| 通话音频通道 SCO 消失，音乐 A2DP 仍连接 | 把 SCO 与音乐输出断开同样处理，主动暂停音乐 | SCO 的移除不再触发通用媒体拔出暂停；仍由通话状态和音频焦点管理通话中断 |
| A2DP/USB/BLE 路由切换 | 只看移除事件，可能在替代输出已出现时暂停 | 保留原有 300ms 去抖，重新检查输出；有替代外部媒体输出时不执行这个拔出暂停 |
| 真正下车、拔掉耳机 | 必须防止音乐转到手机扬声器 | 保留 noisy 广播暂停及媒体输出拔出暂停；即使此前因接电话已暂停，也撤销通话后的恢复意图 |
| 电话只有 mode 回调、没有 focus 回调 | 进入通话会暂停，退出通话没有对应恢复 | 同时跟踪通话状态与焦点；两者都释放后才恢复一次 |
| 同一通话同时送来 mode 与 focus 回调 | 重复暂停可能清掉原来的恢复标记 | 同一中断只发一次暂停；重复事件不覆盖恢复意图 |
| 永久失去音频焦点、用户主动暂停、注销 | 不应由稍后的回调擅自恢复 | 永久失焦与断开输出禁止自动恢复；主动控制及清理播放器撤销恢复标记 |

路由去抖不代表每次播放都增加 300ms；它只用于外部音频设备移除后的检查。

同步移植四个上游音频修复，保留原作者和 cherry-pick 来源：

- `4cdd2062`：时钟过滤器仅在有一致证据时重新对齐，避免把网络 RTT 抖动当成时钟跳变。
- `e22a24d5`：Android 统一使用包含休眠时间的单调时钟，补解码与调度诊断。
- `344676c8`：使用默认 AudioTrack performance mode，避免特定 aptX Adaptive 配置在前后台切换时切换低延迟模式；播放头跟踪适配混音器步进。
- `8cbc6c0c`：重采样保持前后块连续，平滑调度校正，减少蓝牙音频断续。

这批上游修复针对已知风险，不代表本机车载编解码器已被确认是 aptX Adaptive。

网络长时间中断且缓冲耗尽时，当前仍会暂停。本轮没有新增无条件网络恢复即播放，也没有引入上游整套 hold/播放调度重构。这样不会为了掩盖停播而把用户下车后的暂停强行恢复，但网络触发的具体问题仍需要客户端证据确认。

若安装后再次发生，安全停车后在 App 设置中使用 `Share logs / 分享日志` 导出，并记录大约时间。不要先结束 App 进程，现有日志是内存环形缓冲。服务端与客户端同一时间线才能区分主动暂停、音频输出异常和网络断流。

候选版本：`0.14.0-voicehub.3`，versionCode `17`，包名 `io.music_assistant.client.voicehub`，沿用 VoiceHub 私有签名，可覆盖同签名的 `.2`，不需先卸载。
